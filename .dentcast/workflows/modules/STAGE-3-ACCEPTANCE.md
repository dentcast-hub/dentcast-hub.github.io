# Stage 3 — working agent-operated staging runner

**Status: delivered for SAFE, LOCAL, OPERATOR-DRIVEN execution; NOT an autonomous publication pipeline.** Scope is `refactor/publishing-modular-workflow`. This stage changed no live agent router, no canonical scientific engine, no production content, and did not merge or deploy.

## Real delivered behavior

1. `tools/dentcast_stage3_route.py` compiles all seven publication route variants into **22 exact phase-scoped substep types** owned by **15 modules**, including paper Part 1/2/3, LiteCast 0.5/0.6, Pulse C6, Build C7/C8, English D, push marker E and final F/paper-only verification.
2. `tools/dentcast_stage3_modules.py` provides **15 callable module-specific validators** (not duplicated scientific logic), with fail-closed input/output, 5-link, LiteCast separation, exact steps and exclusion checks.
3. `tools/dentcast_stage3_orchestrator.py` provides **begin / next / submit / recover / status**, receipts and local optimistic checkpointing; it cannot label an actual publication successful.
4. `tools/dentcast_stage3_bridge.py` exposes **task / attest / confirm / status**. It packages pinned source instructions and step-specific schemas, independently checks actual bytes of changed files in a disposable workspace, and advances the saved checkpoint **only after verification**. A stale or edited receipt fails closed.
5. `tools/dentcast_stage3_apply.py` is the **actual file-changing executor**: an agent supplies exact changes plus previous file hashes; it checks the marked disposable workspace, exact step fingerprint, declared gate assertions, write ownership, symlink/path traversal safeguards and stale versions, then writes the files and creates an artifact receipt. Existing live repository paths and protected protocols are forbidden. Edits to the fa↔en article pair are explicitly supported.
6. GitHub Actions executes negative and full CLI integration tests, including a real local page-file edit, independent hash receipt, atomic checkpoint and recovery logic. Independent contract audit remains green.

**This architecture deliberately uses the existing editing/research abilities of Claude Code, Cursor or Codex as the domain operator.** For semantic classification, page creation, DES/Fidelity, and other expert work, the *agent* must read the complete pinned module-source document and produce a proposal/result. There is no hidden background autonomous agent or claim that the Python validator computes a clinical/scientific judgment. Founder decisions cannot be generated by the tool and synthetic approvals are not valid for production.

## One-step-at-a-time operator sequence

Use an explicit, genuinely disposable copy of the checkout **outside** the active repo. The example below is staging only and never pushes or publishes.

```bash
# Prepare a disposable copy, and inside its root mark that it is not live.
# (Use any directory OUTSIDE the current Git checkout.)
printf '%s\n' '{"purpose":"dentcast-stage3-disposable-test","allow_real_publication":false,"allow_remote_mutation":false}' \
  > /tmp/dentcast-staging-copy/.dentcast-stage3-disposable-workspace.json

# From the source checkout, prepare a request JSON:
# {"has_text":true,"has_paper":false,"category":"clinical","challenge":false}
python3 tools/dentcast_stage3_orchestrator.py begin \
  --request /tmp/dentcast-request.json --run-id test-001 \
  --revision "$(git rev-parse HEAD)" \
  --state /tmp/dentcast-checkpoint.json

python3 tools/dentcast_stage3_bridge.py task \
  --state /tmp/dentcast-checkpoint.json

# An operator processes the task from its pinned canonical source and records
# its REAL output; for write steps, provide an intent JSON with previous hashes:
python3 tools/dentcast_stage3_apply.py \
  --state /tmp/dentcast-checkpoint.json \
  --workspace /tmp/dentcast-staging-copy \
  --intent /tmp/dentcast-agent-intent.json \
  --receipt /tmp/dentcast-artifact-receipt.json

# The operator separately supplies its step-specific report JSON.
python3 tools/dentcast_stage3_bridge.py confirm \
  --state /tmp/dentcast-checkpoint.json \
  --workspace /tmp/dentcast-staging-copy \
  --receipt /tmp/dentcast-artifact-receipt.json \
  --report /tmp/dentcast-agent-report.json

# Then request the next task; failures preserve the checkpoint.
python3 tools/dentcast_stage3_bridge.py task --state /tmp/dentcast-checkpoint.json
```

Non-file steps (intake, taxonomy, Drive upload requests and verify) must report honest external results and use `bridge attest` for local evidence; **no external GitHub, Drive, notification, or admin mutations are provided here.** Real publication writes are intentionally unavailable. A gate *assertion* in a sandbox intent is not a cryptographically verified founder approval; production approval verification remains a separate requirement.
