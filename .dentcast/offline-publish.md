# انتشار در دورهٔ قطعِ اینترنتِ بین‌الملل

> مرجعِ کانونی. تریگر: «اینترنت بین‌الملل قطع شد»، «حالت قطعی»، «سایت رو استاتیک کن»،
> «از لپ‌تاپ منتشر کن». روترها (`CLAUDE.md`، `AGENTS.md`، `.cursor/rules/dentcast-router.mdc`)
> فقط به این فایل اشاره می‌کنند.

## نقشه در یک نگاه

| | خواننده | در قطعی |
|---|---|---|
| `dentcast.ir` (آروان) | داخلِ ایران | **همه‌چیز می‌ماند** — API، صوت، ویدئو، پیامک، بله، زیبال، فونت، همه داخلی‌اند |
| `dentcast.org` (Cloudflare Pages) | خارج از ایران | **سایتِ استاتیک**: متن‌ها خوانده می‌شوند؛ API، ورود و امکاناتِ پلاس نیست؛ صوت و ویدئو از پلیرِ خارجیِ کنارِ هر پلیرِ داخلی |

و یک واقعیتِ سوم که همه‌چیزِ این فایل از آن می‌آید: **GitHub از داخلِ ایران در دسترس نیست و
runnerهای GitHub به آروان نمی‌رسند.** یعنی دو ورک‌فلوی پس از مرج — `sitemap_only.yml`
(سایت‌مپ، ایندکسِ پلاس، مُهرِ نسخه) و `deploy-arvan.yml` (ساختنِ `.ir`) — هر دو می‌میرند،
و تنها راهِ رسیدن به `.ir`، لپ‌تاپی است که clone و کلیدها را از قبل دارد.

## سایت بدونِ هیچ کاری چه می‌کند

**انتشار در قطعی اختیاری است.** اگر چیزی منتشر نکنی، هر دو دامنه همان محتوای پیش از
قطعی را به‌صورت عادی سرو می‌کنند و لازم نیست به هیچ چیزِ این فایل دست بزنی.

متنِ هر صفحه HTMLِ استاتیک است و همیشه **اول** نمایش داده می‌شود: هر CSS و اسکریپتی که
رندر را نگه می‌دارد محلی است، فونت‌ها روی خودِ سایت‌اند، و API، GA و تبلیغ همه **بعد از**
نمایشِ متن سراغِ شبکه می‌روند. پس API مرده هیچ‌وقت متن را عقب نمی‌اندازد؛ فقط سطوحی که
خواننده را می‌شناسند (حساب، قلب، تب پریمیوم) تا جواب نیامده «نامعلوم»اند.

برای اینکه همین «نامعلوم» هم طول نکشد، `plus/js/api.js` «API نیست» را برای هر تب
به‌خاطر می‌سپارد (`dcp:api-down`، **دو دقیقه**) — با **دو ضربه**: پروبِ ساکت (۱٫۵ ثانیه)
به‌تنهایی چیزی ثبت نمی‌کند (روی اینترنتِ کندِ موبایل، پروب ممکن است در برابرِ APIِ سالم
هم timeout بخورد). یادداشت فقط در یکی از این سه حالت نوشته می‌شود:

- درخواستِ بعد از پروبِ ساکت هم در شبکه شکست بخورد؛
- پروبِ ساکتِ **دوم** در همان تب (شمارش بین صفحه‌ها می‌ماند: `dcp:api-strikes`، پنج
  دقیقه)، و بعد یک در زدنِ **۶ثانیه‌ای** که آن هم بی‌جواب بماند. APIِ زنده با اینترنتِ
  کند هم زیرِ ۶ ثانیه جواب می‌دهد؛
- Cloudflare بگوید origin مرده (۵۲۱–۵۲۴، ۵۳۰).

درخواستی که با ترکِ صفحه لغو شده ضربه نیست، و ورود، خروج و دکمهٔ حساب همیشه واقعاً
می‌پرسند — پس خوانندهٔ `.org` که API را از پشتِ مسیرِ بین‌المللی کند می‌بیند هیچ‌وقت
به‌اشتباه «بیرون» نمی‌ماند؛ اولین جوابِ موفق هم آدرس را یاد می‌گیرد تا صفحه‌های بعد
دوباره پروب نفرستند. در قطعیِ واقعی، صفحهٔ دومِ هر تب حدود ۷٫۵ ثانیه «نامعلوم» می‌ماند
(متن از لحظهٔ اول دیده می‌شود)، صفحه‌های بعد **هیچ** درخواستی نمی‌فرستند، و هر دو
دقیقه یک صفحه یک بار دیگر ۶ ثانیه در می‌زند.

**صوت در صفحهٔ تک‌اپیزود:** فایل از آروان می‌آید و در قطعی به خوانندهٔ خارج نمی‌رسد.
اگر پخش خطا بدهد یا تا ۱۰ ثانیه شروع نشود، زیرِ پلیر جملهٔ «پخش شروع نشد؟ این قسمت
روی Acast هم هست» با لینک به صفحهٔ برنامه در Acast ظاهر می‌شود
(`plus/js/audio-fallback.js`). روزِ عادی دیده نمی‌شود. لینک به برنامه است، نه به خودِ
اپیزود، چون آدرسِ Acastِ هر اپیزود در ریپو نیست.

## قبل از قطعی (یک بار، همین حالا)

1. **clone کامل** روی لپ‌تاپ: `git rev-parse --is-shallow-repository` باید `false` بگوید؛
   اگر نه: `git fetch --unshallow`. سایت‌مپ تاریخِ هر صفحه را از تاریخچهٔ git می‌خواند.
2. **ابزارها:** `git`، `python3`، `node` (۲۲)، و AWS CLI: `python3 -m pip install awscli`.
3. **کلیدهای آروان** در `.deploy-frontend.env` در ریشهٔ ریپو (gitignore شده؛ قالبش سرِ
   `deploy-frontend.sh` نوشته شده). آزمایش: `./deploy-frontend.sh --skip-push --dry-run`.
4. **تصویرِ API:** ساختنش به Docker Hub (`node:20-alpine`) و npm نیاز دارد که هر دو خارجی‌اند.
   حالا یک بار `./plus-api/deploy.sh` را کامل اجرا کن تا لایه‌ها روی لپ‌تاپ کش شوند؛ در قطعی
   تغییری که `package.json`/`package-lock.json` را دست نزند از همان کش ساخته می‌شود. تغییرِ
   وابستگی‌ها در قطعی ممکن نیست مگر از راهِ mirrorِ Docker/npm آروان (پیش از قطعی امتحانش کن).
5. **ایجنتِ محلی** (Ollama در VS Code): افزونه‌ات را طوری تنظیم کن که `AGENTS.md` را به‌عنوان
   قواعدِ همیشگی بخواند. همان روتری است که Cursor و Codex می‌خوانند.
6. **یک تمرینِ کامل:** یک تغییرِ کوچک ← `tools/publish-local.sh` ← `./deploy-frontend.sh --skip-push --dry-run`.

## سوئیچ حالت استاتیک .org

در `plus/js/config.js`:

```js
export const STATIC_HOSTS = ['dentcast.org'];   // قطعی؛ در حالت عادی: []
```

بعد `python3 tools/asset_version.py --bump`، کامیت و `git push origin main`. Cloudflare Pages
`.org` را از GitHub می‌سازد، پس این push باید از **بیرونِ** شبکهٔ قطع‌شده انجام شود
(یک همکارِ خارج از ایران، VPN، یا یک جلسهٔ Claude Code در وب). اگر هیچ‌کدام نشد، **رها کن** —
لایهٔ خودکارِ بالا کافی است. سوئیچ به hostname گره خورده، پس اگر همین کامیت روزی به `.ir`
هم برسد آن‌جا اثری ندارد.

در حالت استاتیک هیچ درخواستی به API نمی‌رود و هر سطحی که خواننده را می‌شناسد در حالتِ
«نتوانستیم بررسی کنیم» می‌ماند. پس از وصل شدن: `STATIC_HOSTS = []`، `--bump`، push.

## در دورهٔ قطعی: انتشارِ حداقلی

**پیش‌فرضِ ایجنتِ آفلاین، انتشارِ حداقلی است، نه ورک‌فلوی کامل:**
`.dentcast/workflows/MINIMAL-PUBLISH.md`. همان سند را گام‌به‌گام اجرا کن، با **دو جایگزینی**،
چون آن سند فرض می‌کند GitHub در دسترس است:

- **گام ۷** («Commit and push to `main`») ⇒ فقط **کامیتِ محلی روی `main`**؛ push نکن.
- **گام ۹** («Actions → Deploy … Run workflow») ⇒ این دو فرمان روی لپ‌تاپ:
  ```bash
  tools/publish-local.sh                     # سایت‌مپ، ایندکسِ پلاس، مُهرِ نسخه — کامیت نمی‌کند، فرمانِ کامیت را چاپ می‌کند
  ./deploy-frontend.sh --skip-push --dry-run
  ./deploy-frontend.sh --skip-push           # ویندوز: .\deploy-frontend.ps1 -SkipPush
  ```
- **گام ۸** (بررسی) روی `https://dentcast.ir/…` انجام می‌شود، نه `.org`.

سه بندِ «Do not skip» همان سند در قطعی هم حیاتی‌اند: `dentcast-brain.json` معتبر بماند
(`python3 -c "import json; json.load(open('dentcast-brain.json'))"`)، ورودی **ته** آرایه
اضافه شود، و canonical دقیقاً `https://dentcast.org/<مسیر>.html` و بدون `noindex` باشد.
`tools/verify_publish.py` در این مسیر **عمداً قرمز** است — خروجی‌اش را نگه دار؛ همان فهرستِ
کارهای معوق است.

**API** (اگر کدش عوض شد — در انتشارِ حداقلی معمولاً نه): `./plus-api/deploy.sh vNN` ←
تعویضِ تگ در پنلِ آروان ← `./plus-api/deploy.sh --verify vNN`.

## کارهایی که در قطعی نباید کرد

- `git push` نکن، `rebase` و `--force` هم نه: کامیت‌ها محلی بمانند تا وصل شدن.
- `deploy-frontend.sh` را بدونِ `--skip-push` اجرا نکن (اول به GitHub سر می‌زند و می‌ایستد).
- مُهرهای `?v=` و `CACHE_NAME` را دستی عوض نکن؛ فقط ابزارها.
- `publish-local.sh` را روی clone کم‌عمق اجرا نکن (خودش هم اجازه نمی‌دهد).

## بعد از وصل شدن

1. `git fetch origin`؛ اگر `origin/main` هم جلو رفته: `git pull origin main` (merge، نه rebase).
   تعارض در فایل‌های تولیدی را دستی حل نکن؛ `tools/publish-local.sh` را دوباره بزن.
2. `git push origin main`. CI دوباره اجرا می‌شود (بی‌ضرر) و `.org` همهٔ مطالبِ دورهٔ قطعی را می‌گیرد.
3. اگر سوئیچ استاتیک روشن بود، خاموشش کن (بالا).
4. **همگام‌سازی کامل** — به ایجنتِ کامل بسپار: برای هر صفحه‌ای که حداقلی منتشر شد، بخشِ
   **Deferred** در `MINIMAL-PUBLISH.md` را اجرا کند (نسخهٔ انگلیسی، کراس‌لینک و «کاوش بیشتر»،
   پیلار، DES، هشتگ‌ها، فلش‌کارت و کوییز، مسیرهای یادگیری، لینکِ صفحهٔ فهرستِ بخش، Pulse)
   تا `tools/verify_publish.py <content_id>` سبز شود.
5. همگرایی: صفحهٔ دورهٔ قطعی را روی هر دو دامنه باز کن؛ `/health` هر دو API باید یک `commit` بدهند.
