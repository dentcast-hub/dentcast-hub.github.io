# انتشار در دورهٔ قطعِ اینترنتِ بین‌الملل

> مرجعِ کانونی. تریگر: «اینترنت بین‌الملل قطع شد»، «حالت قطعی»، «سایت رو استاتیک کن»،
> «از لپ‌تاپ منتشر کن». روترها (`CLAUDE.md`، `AGENTS.md`، `.cursor/rules/dentcast-router.mdc`)
> فقط به این فایل اشاره می‌کنند.

## نقشه در یک نگاه

| | خواننده | در قطعی |
|---|---|---|
| `dentcast.ir` (آروان) | داخلِ ایران | **همه‌چیز می‌ماند** — API، صوت، ویدئو، پیامک، بله، زیبال، فونت، همه داخلی‌اند |
| `dentcast.org` (Cloudflare Pages) | خارج از ایران | **سایتِ استاتیک**: متن‌ها خوانده می‌شوند؛ API، ورود و امکاناتِ پلاس نیست؛ صوت و ویدئو از پلیرِ خارجیِ کنارِ هر پلیرِ داخلی |

و یک واقعیتِ سوم که همه‌چیزِ این فایل از آن می‌آید: **GitHub از داخلِ ایران در دسترس نیست و
runnerهای GitHub به آروان نمی‌رسند.** یعنی دو ورک‌فلوی پس از مرج — `sitemap_only.yml`
(سایت‌مپ، ایندکسِ پلاس، مُهرِ نسخه) و `deploy-arvan.yml` (ساختنِ `.ir`) — هر دو می‌میرند،
و تنها راهِ رسیدن به `.ir`، لپ‌تاپی است که clone و کلیدها را از قبل دارد.

## سایت بدونِ هیچ کاری چه می‌کند

`plus/js/api.js` «API نیست» را برای هر تب به‌خاطر می‌سپارد (`dcp:api-down` در
sessionStorage، دو دقیقه): وقتی هر دو آینهٔ API ساکت‌اند یا Cloudflare می‌گوید origin
مرده (۵۲۱–۵۲۴، ۵۳۰)، صفحهٔ اول فقط ۱٫۵ ثانیهٔ پروب را می‌پردازد و صفحه‌های بعد **هیچ**
درخواستی نمی‌فرستند؛ همهٔ سطوح بی‌درنگ به حالتِ «نتوانستیم بررسی کنیم» می‌رسند که از
قبل طراحی شده. `/me` هم سقفِ ۸ ثانیه دارد. پس `.org` در قطعی **بدونِ سوئیچ هم** کند
نمی‌شود — سوئیچِ پایین فقط همان ۱٫۵ ثانیهٔ صفحهٔ اول را هم حذف می‌کند.

## قبل از قطعی (یک بار، همین حالا)

1. **clone کامل** روی لپ‌تاپ: `git rev-parse --is-shallow-repository` باید `false` بگوید؛
   اگر نه: `git fetch --unshallow`. سایت‌مپ تاریخِ هر صفحه را از تاریخچهٔ git می‌خواند.
2. **ابزارها:** `git`، `python3`، `node` (۲۲)، و AWS CLI: `python3 -m pip install awscli`.
3. **کلیدهای آروان** در `.deploy-frontend.env` در ریشهٔ ریپو (gitignore شده؛ قالبش سرِ
   `deploy-frontend.sh` نوشته شده). آزمایش: `./deploy-frontend.sh --skip-push --dry-run`.
4. **تصویرِ API:** ساختنش به Docker Hub (`node:20-alpine`) و npm نیاز دارد که هر دو خارجی‌اند.
   حالا یک بار `./plus-api/deploy.sh` را کامل اجرا کن تا لایه‌ها روی لپ‌تاپ کش شوند؛ در قطعی
   تغییری که `package.json`/`package-lock.json` را دست نزند از همان کش ساخته می‌شود. تغییرِ
   وابستگی‌ها در قطعی ممکن نیست مگر از راهِ mirrorِ Docker/npm آروان (پیش از قطعی امتحانش کن).
5. **ایجنتِ محلی** (Ollama در VS Code): افزونه‌ات را طوری تنظیم کن که `AGENTS.md` را به‌عنوان
   قواعدِ همیشگی بخواند. همان روتری است که Cursor و Codex می‌خوانند.
6. **یک تمرینِ کامل:** یک تغییرِ کوچک ← `tools/publish-local.sh` ← `./deploy-frontend.sh --skip-push --dry-run`.

## سوئیچ حالت استاتیک .org

در `plus/js/config.js`:

```js
export const STATIC_HOSTS = ['dentcast.org'];   // قطعی؛ در حالت عادی: []
```

بعد `python3 tools/asset_version.py --bump`، کامیت و `git push origin main`. Cloudflare Pages
`.org` را از GitHub می‌سازد، پس این push باید از **بیرونِ** شبکهٔ قطع‌شده انجام شود
(یک همکارِ خارج از ایران، VPN، یا یک جلسهٔ Claude Code در وب). اگر هیچ‌کدام نشد، **رها کن** —
لایهٔ خودکارِ بالا کافی است. سوئیچ به hostname گره خورده، پس اگر همین کامیت روزی به `.ir`
هم برسد آن‌جا اثری ندارد.

در حالت استاتیک هیچ درخواستی به API نمی‌رود و هر سطحی که خواننده را می‌شناسد در حالتِ
«نتوانستیم بررسی کنیم» می‌ماند. پس از وصل شدن: `STATIC_HOSTS = []`، `--bump`، push.

## در دورهٔ قطعی: انتشارِ یک مطلب

1. **نوشتن** با ایجنتِ محلی، از همان روترِ همیشگی (`.dentcast/workflows/README.md`).
   آنچه در قطعی نیست و ورک‌فلو برایش مسیرِ مجاز دارد (`agent-parity.md`، «توانمندی ندارم»):
   - **DES (گام ۴.۱۳):** PubMed و WebFetch نیست ⇒ اول کابینتِ محلی، وگرنه
     `INSUFFICIENT_TEXT` یا «بدون DES منتشر بشه» — هرگز امتیازِ ساخته‌شده از متنِ خودِ دنت‌کست.
   - **فایلِ مقاله (گام ۴.۱۰):** Drive نیست ⇒ آپلود و ردیفِ کاتالوگ بماند برای بعد از وصل شدن.
   - **DOI و نویسندهٔ اول:** جست‌وجوی وب نیست ⇒ از خودت بپرسد، حدس نزند.
   - **نسخهٔ انگلیسی (فاز D):** ترجمه با مدلِ محلی.
2. **دروازه** — مدلِ محلی کوچک‌تر است و گام جا می‌اندازد؛ این فرمان همان چیزی است که جا افتادن را می‌گیرد:
   ```bash
   python3 tools/verify_publish.py <content_id> --expect-title "…" --expect-caption "…"
   python3 tools/asset_version.py --check
   ```
   خروجِ غیرصفر یعنی انتشار ناقص است؛ هر ردیفِ `FAIL` فرمانِ اصلاحِ خودش را چاپ می‌کند.
3. **کامیتِ محلی** روی `main`.
4. **ایندکس‌ها:** `tools/publish-local.sh` — همان سه فرمانِ `sitemap_only.yml`؛ کامیت نمی‌کند،
   فایل‌های عوض‌شده و فرمانِ کامیت را چاپ می‌کند.
5. **انتشار روی .ir:**
   ```bash
   ./deploy-frontend.sh --skip-push --dry-run
   ./deploy-frontend.sh --skip-push          # ویندوز: .\deploy-frontend.ps1 -SkipPush
   ```
6. **بررسی:** `curl -sI https://dentcast.ir/<مسیر-صفحه>` باید `200` بدهد.

**API** (اگر کدش عوض شد): `./plus-api/deploy.sh vNN` ← تعویضِ تگ در پنلِ آروان ←
`./plus-api/deploy.sh --verify vNN`. تغییرِ `pathways.json`/`badges.json`/ایندکس‌ها
deploy لازم ندارد: `content-refresh.ts` اول از `dentcast.ir` می‌خواند.

## کارهایی که در قطعی نباید کرد

- `git push` نکن، `rebase` و `--force` هم نه: کامیت‌ها محلی بمانند تا وصل شدن.
- `deploy-frontend.sh` را بدونِ `--skip-push` اجرا نکن (اول به GitHub سر می‌زند و می‌ایستد).
- مُهرهای `?v=` و `CACHE_NAME` را دستی عوض نکن؛ فقط ابزارها.
- `publish-local.sh` را روی clone کم‌عمق اجرا نکن (خودش هم اجازه نمی‌دهد).

## بعد از وصل شدن

1. `git fetch origin`؛ اگر `origin/main` هم جلو رفته (مثلاً کامیتِ سوئیچ): `git pull origin main`
   (merge، نه rebase). تعارض در فایل‌های تولیدی را دستی حل نکن؛ `tools/publish-local.sh` را دوباره بزن.
2. `git push origin main`. CI دوباره اجرا می‌شود: `sitemap_only` همان فایل‌ها را بازسازی می‌کند
   (بی‌ضرر)، `deploy-arvan` `.ir` را با همان محتوا همگام می‌کند، و `.org` همهٔ مطالبِ دورهٔ قطعی را می‌گیرد.
3. سوئیچ استاتیک را خاموش کن (بالا).
4. گام‌های معوق: آپلودِ Drive و ردیفِ کاتالوگِ مقاله‌ها، DESِ منابعی که `INSUFFICIENT_TEXT` شدند.
5. همگرایی: یک صفحهٔ دورهٔ قطعی را روی هر دو دامنه باز کن؛ `GET https://api.dentcast.ir/health` و
   `https://api.dentcast.org/health` باید یک `commit` بدهند.
