# پروتکل انتشار در روز قیامت

> راهنمای ساده و مرحله‌به‌مرحله برای وقتی که اینترنت بین‌المللِ ایران قطع می‌شود.
> این فایل خلاصهٔ کاربردیِ `.dentcast/offline-publish.md` است؛ اگر جایی با آن فرق داشت،
> **همان فایل مرجع است**. مسیرِ انتشارِ حداقلی هم در
> `.dentcast/workflows/MINIMAL-PUBLISH.md` آمده است.
> تریگرها: «اینترنت بین‌الملل قطع شد»، «حالت قطعی»، «سایت رو استاتیک کن»، «از لپ‌تاپ منتشر کن».

همهٔ مراحلِ زیر روی **لپ‌تاپی** انجام می‌شود که ایجنتِ Ollama روی آن اجراست.

## چرا لپ‌تاپ؟

GitHub از داخلِ ایران بالا نمی‌آید و runnerهای GitHub هم به آروان نمی‌رسند. پس
`sitemap_only.yml` و `deploy-arvan.yml` هر دو در قطعی می‌میرند و تنها راهِ رسیدن به
`dentcast.ir` همین لپ‌تاپ است.

## اگر هیچ‌چیز منتشر نکنی

هر دو سایت همان محتوای پیش از قطعی را عادی سرو می‌کنند و **لازم نیست به هیچ‌چیزِ این فایل
دست بزنی.** این مراحل فقط برای وقتی است که بخواهی در قطعی مطلبِ جدید بگذاری.

---

## بخش ۱: قبل از قطعی (فقط یک بار)

### مرحله ۱: ریپو را کامل داشته باش

داخل پوشهٔ ریپو بزن:

```
git rev-parse --is-shallow-repository
```

- اگر نوشت `false`، خوب است.
- اگر نوشت `true`، این را بزن: `git fetch --unshallow`

(سایت‌مپ تاریخِ هر صفحه را از تاریخچهٔ git می‌خواند، و `publish-local.sh` روی clone کم‌عمق
اجرا نمی‌شود.)

### مرحله ۲: برنامه‌ها نصب باشند

روی لپ‌تاپ باید این‌ها باشد: `git`، `python3`، `node` (نسخهٔ ۲۲). بعد:

```
python3 -m pip install awscli
```

### مرحله ۳: کلیدهای آروان

در پوشهٔ اصلیِ ریپو فایلی به نام `.deploy-frontend.env` بساز (این فایل gitignore شده است و
هیچ‌وقت نباید کامیت شود) و این چهار خط را با کلیدهای خودت در آن بگذار:

```
ARVAN_ACCESS_KEY=...
ARVAN_SECRET_KEY=...
ARVAN_BUCKET=dentcast
ARVAN_ENDPOINT=https://s3.ir-thr-at1.arvanstorage.ir
```

کلیدها را از پنل آروان، بخش Object Storage و بعد Access Keys برمی‌داری.

### مرحله ۴: تستِ آروان

```
./deploy-frontend.sh --skip-push --dry-run
```

یعنی «فقط نشان بده چه چیزی آپلود می‌شود، چیزی آپلود نکن». اگر خطا نداد، کلیدها درست‌اند.

### مرحله ۵: به ایجنت بگو قوانین را بخواند

در تنظیماتِ افزونهٔ Ollama (VS Code)، فایلِ `AGENTS.md` را به‌عنوان «قواعدِ همیشگی» بده.
همان روتری است که Cursor و Codex هم می‌خوانند.

### مرحله ۶: یک تمرینِ واقعی

یک تغییرِ خیلی کوچک بده (مثلاً یک کلمه) و بعد:

```
tools/publish-local.sh
./deploy-frontend.sh --skip-push --dry-run
```

اگر هر دو بدون خطا رد شدند، آماده‌ای. تغییرِ تمرینی را بعدش برگردان.

### مرحله ۷: کشِ تصویرِ API (فقط اگر ممکن است کدِ API را عوض کنی)

ساختنِ تصویرِ API به Docker Hub و npm نیاز دارد که هر دو خارجی‌اند. یک بار
`./plus-api/deploy.sh` را کامل اجرا کن تا لایه‌ها روی لپ‌تاپ کش شوند. در قطعی، هر تغییری که
`package.json` و `package-lock.json` را دست نزند از همان کش ساخته می‌شود. تغییرِ وابستگی‌ها
در قطعی ممکن نیست، مگر با mirrorِ Docker/npm آروان که باید پیش از قطعی امتحانش کنی.

### اختیاری: سوئیچِ استاتیکِ `.org`

در `plus/js/config.js` مقدارِ `STATIC_HOSTS = ['dentcast.org']` می‌شود (در حالت عادی `[]`)،
بعد `python3 tools/asset_version.py --bump`، کامیت و push. ولی این push باید از **بیرونِ**
شبکهٔ قطع‌شده برود (همکارِ خارج از ایران، VPN، یا یک جلسهٔ Claude Code در وب)، چون Cloudflare
Pages از GitHub می‌سازد. اگر نشد، **رهایش کن**؛ لایهٔ خودکارِ `plus/js/api.js` کافی است.

## بخش ۲: وقتی اینترنت قطع شد و خواستی چیزی منتشر کنی

به ایجنت بگو «حالت قطعی» و بگو فایلِ `.dentcast/workflows/MINIMAL-PUBLISH.md` را اجرا کند،
با این **دو جایگزینی**:

1. گامِ ۷ (کامیت و push): **فقط کامیتِ محلی روی `main`**؛ push نکند.
2. گامِ ۹ (دیپلوی `.ir`): به‌جای Actions، این دو فرمان:

```
tools/publish-local.sh
./deploy-frontend.sh --skip-push
```

(روی ویندوز: `.\deploy-frontend.ps1 -SkipPush`.)

بعد صفحه را روی `https://dentcast.ir/…` باز کن (نه `.org`) و ببین آمده یا نه.

### سه چیزی که نباید جا بیفتد

1. `dentcast-brain.json` معتبر بماند:
   `python3 -c "import json; json.load(open('dentcast-brain.json'))"`
2. ورودیِ جدید **ته** آرایه اضافه شود، نه وسط.
3. canonical دقیقاً `https://dentcast.org/<مسیر>.html` باشد و صفحه `noindex` نداشته باشد.

### یک نکته

`tools/verify_publish.py` در این مسیر **عمداً قرمز** است. خروجی‌اش را نگه دار؛ همان فهرستِ
کارهای معوق است.

### این‌ها را هیچ‌وقت نزن

- `git push`، `git rebase` و `--force`
- `./deploy-frontend.sh` بدونِ `--skip-push` (اول به GitHub سر می‌زند و می‌ایستد)
- تغییرِ دستیِ مُهرهای `?v=` و `CACHE_NAME` (فقط با ابزارها)
- `publish-local.sh` روی clone کم‌عمق

### محدودیت

LiteCast و واژه‌های دانشنامه در این مسیر پوشش داده نشده‌اند.

## بخش ۳: بعد از وصل شدنِ اینترنت

1. `git fetch origin` و بعد `git pull origin main` (**merge**، نه rebase). اگر در فایل‌های
   تولیدی تعارض بود، دستی حل نکن؛ `tools/publish-local.sh` را دوباره بزن.
2. `git push origin main`. CI دوباره اجرا می‌شود (بی‌ضرر) و `.org` همهٔ مطالبِ دورهٔ قطعی
   را می‌گیرد.
3. اگر سوئیچِ استاتیک روشن بود، خاموشش کن: `STATIC_HOSTS = []`، بعد
   `python3 tools/asset_version.py --bump`، کامیت و push.
4. کارهای عقب‌مانده را به یک ایجنتِ کامل بسپار: برای هر صفحه‌ای که حداقلی منتشر شد، بخشِ
   **Deferred** در `MINIMAL-PUBLISH.md` (نسخهٔ انگلیسی، کراس‌لینک و «کاوش بیشتر»، پیلار،
   DES، هشتگ‌ها، فلش‌کارت و کوییز، مسیرهای یادگیری، لینکِ صفحهٔ فهرستِ بخش، Pulse) تا
   `python3 tools/verify_publish.py <content_id>` سبز شود.
5. صفحهٔ دورهٔ قطعی را روی هر دو دامنه باز کن؛ `/health` هر دو API باید یک `commit` یکسان بدهند.
