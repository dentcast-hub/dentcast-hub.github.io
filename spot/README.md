# سیستم تبلیغات دنت‌کست (Spot)

همه‌چیز از **یک فایل** کنترل می‌شود: `spot/spot-config.json`. هیچ صفحه‌ای مارک‌آپ تبلیغ ندارد؛
لودر داخل `dc-nav.js` فایل `spot/spot.js` را روی همهٔ صفحه‌ها بارگذاری می‌کند و آن اسکریپت
بر اساس کانفیگ تصمیم می‌گیرد. **اگر چیزی خاموش باشد، هیچ اثری روی صفحه نمی‌ماند**
(نه DOM، نه CSS).

## چرا «Spot» و نه «Ad»؟ (قانون نام‌گذاری — دست نزنید)

لیست‌های فیلترِ ادبلاکرها (EasyList — مبنای بلاکر داخلی اپرا، uBlock،
AdBlock Plus و AdGuard) قاعدهٔ عمومی `##.dc-ad` را دارند و مسیرهای «ad»دار را
هم به‌سادگی هدف می‌گیرند؛ نسخهٔ قبلی این سیستم (کلاس `dc-ad`، پوشهٔ `/ads/`)
دقیقاً به همین دلیل برای هر کاربر ادبلاک‌دار نامرئی بود. بنابراین:

- در **هیچ‌کدام** از اسم فایل، مسیر URL، کلاس CSS، id یا data-attribute این
  سیستم کلمهٔ «ad/ads» به کار نرود — پیشوند رسمی `dc-spot` و مسیر `/spot/` است.
- هر نام جدید (کلاس، فایل، پوشهٔ عکس) قبل از انتشار باید علیه EasyList چک شود
  (قواعد شبکه + قواعد `##` مخفی‌سازی).
- کلیدهای localStorage (`dcAds.*`) و رویدادهای GA (`ad_impression`/`ad_click`)
  عمداً با نام قدیمی مانده‌اند — برای بلاکرها نامرئی‌اند و تغییرشان تداوم
  آمار و چرخش را می‌شکند.

## قانون نمایش

- مهمان (لاگین‌نشده): تبلیغ می‌بیند ✅
- کاربر پلاس رایگان: تبلیغ می‌بیند ✅
- کاربر پریمیوم (`tier === 'premium'`): هیچ تبلیغی، هیچ‌جا ❌ («بدون تبلیغات» مزیت پریمیوم است)
- حالت میز کار (مطالعهٔ فعال): تبلیغ موقتاً مخفی می‌شود تا تجربهٔ مطالعه تمیز بماند.

## کلیدهای خاموش/روشن

```jsonc
"enabled": true          // کلید سراسری — false یعنی کل سیستم خاموش
"slots": {
  "article":   { "enabled": true },  // باکس داخل مقاله‌ها
  "home":      { "enabled": true },  // کارت بعد از پالس در صفحهٔ اصلی
  "player":    { "enabled": true },  // بنر بالای «جستجو در دنت‌کست» در player.html
  "episodes":  { "enabled": true },  // کارت زیر «اپیزود پیشنهادی» در episodes.html
  "dashboard": { "enabled": true },  // کارت زیر باکس «استریک» در پیشخوان پلاس
  "profile":   { "enabled": true },  // کارت زیر باکس «پلن» در پروفایل پلاس
  "search":    { "enabled": true }   // کارت در اورلی جستجوی سراسری (بین دکمه‌های فیلتر و نتایج)
}
```

اسلات `search` روی همهٔ صفحه‌هاست (شیت `#dcGlobalBox`): کارت بین ردیف
دکمه‌های فیلتر و باکس نتایج می‌نشیند، اما فقط با **اولین بازشدنِ** اورلی
تزریق و شمرده می‌شود — تا وقتی کاربر جستجو را باز نکرده، نه DOM اضافه می‌شود
نه ایمپرشنی ثبت می‌شود.

اسلات‌های `dashboard` و `profile` هم DOM-محورند نه URL-محور: پیشخوان و پروفایل هم به‌صورت صفحهٔ مستقل
(`/plus/` و `/plus/profile.html`) و هم به‌صورت اورلی هدر روی هر صفحه‌ای رندر
می‌شوند؛ موتور، بخش لنگر («استریک» / «پلن») را در DOM رصد می‌کند و با هر بار
بازشدن، کارت را دوباره زیر همان بخش می‌نشاند. این دو نما فقط برای کاربر
لاگین‌شده رندر می‌شوند، پس مخاطب‌شان عملاً همیشه `plus` است.

## هدف‌گیری مخاطب (audience)

هر کریتیو (پریمیوم یا اسپانسر) می‌تواند فیلد اختیاری `audience` داشته باشد:

```jsonc
"audience": ["anon"]          // فقط بازدیدکنندهٔ لاگین‌نشده
"audience": ["plus"]          // فقط کاربر لاگین‌شدهٔ غیرپریمیوم
// بدون فیلد audience = همه (پیش‌فرض — همان تجربهٔ یکسان برای همه)
```

کاربر پریمیوم طبق قانون همیشگی هیچ تبلیغی نمی‌بیند و مقدار جداگانه‌ای ندارد.
اگر کریتیوِ قدمِ چرخش برای مخاطب فعلی مجاز نباشد، مثل `slots` به نوع دیگر
فال‌بک می‌شود؛ هیچ گزینهٔ مجازی نباشد → هیچ چیزی رندر نمی‌شود.

نمونه — لاگین‌نشده دعوت به پلاس ببیند، لاگین‌شده تبلیغ اسپانسر:

```jsonc
"premium":  { ..., "audience": ["anon"] },
"sponsors": [ { "id": "sponsor-x", ..., "audience": ["plus"] } ]
```

## جای تبلیغ در مقاله

```jsonc
"article": {
  "position": "middle",     // middle | end | top
  "min_paragraphs": 8,      // مقاله‌های کوتاه‌تر از این تعداد پاراگراف، تبلیغ وسط نمی‌گیرند
  "fallback": "end"         // برای مقاله‌های کوتاه: "end" (آخر مقاله) یا "none" (هیچ)
}
```

«وسط» یعنی قبل از سرتیترِ میانی مقاله (مرز دو بخش) — هیچ‌وقت وسط جمله یا داخل لیست/جدول
نمی‌نشیند، قابل هایلایت‌شدن در میز کار نیست، و حداکثر یک تبلیغ در هر مقاله است.

## چرخش پریمیوم/اسپانسر

`rotation.sequence` یک آرایهٔ چرخشی است؛ با هر بازدیدِ تبلیغ‌دار یک قدم جلو می‌رود
(شمارنده در مرورگر کاربر). مقادیر مجاز: `"premium"`، `"sponsor"` (چرخش وزنی بین
اسپانسرهای روشن)، یا id یک اسپانسر خاص.

```jsonc
// همیشه تبلیغ پریمیوم (پیش‌فرض):
"sequence": ["premium"]

// هر ۵ مقاله یک اسپانسر، بقیه پریمیوم:
"sequence": ["premium", "premium", "premium", "premium", "sponsor"]

// هر ۴ بار اسپانسر، یک بار پریمیوم:
"sequence": ["sponsor", "sponsor", "sponsor", "sponsor", "premium"]

// جای خاص برای یک اسپانسر مشخص:
"sequence": ["sponsor-x", "premium"]
```

اگر در قدمِ `sponsor` هیچ اسپانسر روشنی نباشد، خودکار تبلیغ پریمیوم نمایش داده می‌شود
(و برعکس). اگر هیچ‌کدام موجود نباشد، هیچ چیزی رندر نمی‌شود.

## افزودن اسپانسر

در آرایهٔ `creatives.sponsors` یک آیتم جدید اضافه کن — متن، لینک و دکمهٔ هر تبلیغ
مستقل از بقیه است:

```jsonc
{
  "id": "sponsor-x",        // یکتا؛ در sequence و رویدادهای GA استفاده می‌شود
  "enabled": true,
  "badge": "حمایت‌شده",     // برچسب روی کارت
  "title": "نام برند",
  "text": "یک خط توضیح.",
  "cta": "بازدید",
  "url": "https://example.com",
  "image": "/spot/img/sponsor-x.webp",  // اختیاری، null یعنی بدون تصویر
  "weight": 2,              // سهم در چرخش وزنی نسبت به بقیهٔ اسپانسرها
  "slots": ["article", "home"],  // اختیاری: فقط در این اسلات‌ها نمایش داده شود؛ حذفش یعنی همه‌جا
  "audience": ["plus"]           // اختیاری: فقط برای این مخاطب (بخش «هدف‌گیری مخاطب»)؛ حذفش یعنی همه
}
```

فیلدهای `slots` و `audience` روی تبلیغ پریمیوم هم کار می‌کنند. فیلدهای اضافهٔ آزاد مثل `note`
(مثلاً تاریخ پایان قرارداد) مجازند — موتور نادیده‌شان می‌گیرد و فقط برای
یادداشت انسانی‌اند.

لینک اسپانسرها (وقتی `http/https` باشد) خودکار `rel="sponsored noopener"` و در
تب جدید باز می‌شود. لینک‌های غیر-وب (مثل `mailto:` پلیس‌هولدر «معرفی برند»)
`rel` نمی‌گیرند — `rel="sponsored"` فقط برای لینک قابل‌خزش گوگل معنا دارد.

## سنجش

هر نمایش و کلیک به GA4 گزارش می‌شود: رویداد `ad_impression` و `ad_click` با
پارامترهای `ad_slot` و `ad_creative`. گزارش اسپانسر = فیلتر روی همین دو رویداد.

## نکته‌های فنی

- تغییر `spot-config.json` فوری اعمال می‌شود (fetch با `no-store`).
- تغییر `spot.js` نیاز به بامپ ورژن دارد: `?v=` در لودر spot داخل `dc-nav.js`.
- **CSS کارت‌ها داخل خود `spot.js` است** (تگ `<style>`، ثابت `SPOT_CSS`) — فایل
  CSS جداگانه‌ای وجود ندارد و نباید ساخته شود: CDN آروان روی آینهٔ `.ir` فایل
  مستقل `spot.css` را دستکاری/مینیفای می‌کرد و مرورگر آن را به‌عنوان استایل‌شیت
  اعمال نمی‌کرد (کارت‌ها بدون استایل رندر می‌شدند). یک فایل، یک درخواست، چیزی
  برای خراب‌کردن نمی‌ماند.
- تشخیص پریمیوم از همان `/me` کش‌شدهٔ پلاس استفاده می‌کند؛ اگر API در دسترس نباشد
  کاربر «رایگان» فرض می‌شود (سایت استاتیک هیچ‌وقت منتظر API نمی‌ماند).
- یک تبلیغ هاردکد قدیمی هنوز خارج از این سیستم است: تبلیغ دیونت داخل کارت پالس
  (`index.html`). ظاهر کارت‌های این سیستم (`SPOT_CSS` داخل `spot.js`) عمداً با همان تم نارنجی
  دیونت هماهنگ است. کارت «معرفی برند» که قبلاً در `episodes.html` هاردکد بود
  حذف شده است.
